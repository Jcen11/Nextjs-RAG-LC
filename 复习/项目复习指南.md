## 一、这个项目是什么（30 秒版本）⭐⭐

**一句话**：一个基于 Next.js + LangChain + RAG 的全栈 AI 知识库助手——用户上传文档建知识库，提问时系统检索相关片段注入 prompt，AI 基于文档流式回答；支持多会话持久化、多轮上下文、Markdown 渲染。

**场景**：个人笔记问答、团队知识库、学习资料助手。

**技术栈**：

- 前端：Next.js 15.4.6（App Router）+ React 19 + TypeScript + Zustand 5 + Tailwind v4 / shadcn-ui
- AI/RAG：LangChain.js v1（ChatOpenAI / OpenAIEmbeddings / RecursiveCharacterTextSplitter / MemoryVectorStore）
- 数据：SQLite（node:sqlite，Node ≥ 22 内置模块）
- 模型：硅基流动（对话 Qwen/Qwen3-8B，嵌入 BAAI/bge-m3）

## 三、现在系统的架构（一张图记住）⭐⭐

```
浏览器
 ├─ Zustand store（lib/store.ts）← 组件外的单一数据源
 │    currentId / messages / conversations / systemPrompt / currentKbId / justCreatedId
 ├─ Sidebar（会话列表/切换/重命名/删除）
 └─ ChatBox（发送/流式/Markdown/中止）
        │ fetch（流式）
────────┼── HTTP ─────────
服务端
 ├─ /api/chat         对话（ChatOpenAI 流式 + RAG 前置）
 ├─ /api/conversations(+[id])  会话增查/删/改名
 ├─ /api/messages     流式结束后保存一轮（事务）
 ├─ /api/knowledge(+[id]/documents)  知识库管理 + 上传文档（切块+嵌入）
 └─ lib/
      langchain.ts  模型工厂（ChatOpenAI + OpenAIEmbeddings 单例）
      rag.ts        切块 / 索引 / 检索 / 拼 prompt
      vectorstore.ts 向量库抽象层（当前 Memory 实现）
      db.ts + queries.ts  SQLite 连接 + CRUD（prepared statements）
        ↓ chat.db
```

**三条贯穿始终的原则**（面试可用）：
1. 前端只对接自己的后端，永远只 `fetch('/api/chat')`，不知道后端接的是谁
2. 服务端是"协议适配层"：前端自定义格式 ↔ 厂商协议，协议切换收敛在 route.ts
3. 密钥永远只在服务端（`process.env`，不进浏览器 bundle）

## 四、一次带 RAG 的完整数据流 + 关键代码 ⭐⭐⭐

### 4.1 前端发送：顺序是关键

`components/ChatBox.tsx` 的 `handleSend`：

```ts
// 必须先把消息写进 store，再处理新建会话 + router.push
// 因为 router.push 会触发组件重建、useEffect 会跑——
// 必须让 store.messages 在 push 之前就有内容
setMessages([...messages, userMessage, assistantMessage]); // 先插用户消息 + 空 assistant 占位

if (!activeConvId) {
  const data = await fetch("/api/conversations", { method: "POST", ... }).then(r => r.json());
  activeConvId = data.id;
  setJustCreatedId(activeConvId);          // 标记"刚建的会话"（防 useEffect 覆盖）
  router.push(`/chat/${activeConvId}`);    // 客户端导航，URL 变成 /chat/[id]
}
```

之后流式读取：`response.body.getReader()` + `TextDecoder` 逐块读 → 每来一段 `updateLastMessage(累积内容)`；**正常结束才** `POST /api/messages` 保存这一轮（未完成/中止不保存）。

### 4.2 竞态 bug 的根治 ⭐⭐⭐（面试点，五轮 debug 的最终答案）

**问题**：新建会话时 `router.push` 导致组件重建，`useEffect` 去数据库加载历史——但消息还没保存，加载到空数组会覆盖刚发出去的消息。补丁失败五轮，最终答案是 **Zustand store + `justCreatedId` 标记**：

```ts
// ChatBox 的 useEffect 里（依赖数组只放 [currentId]）
const createdId = useChatStore.getState().justCreatedId; // 用 getState 读，不订阅！
if (createdId) {
  if (currentId === createdId) setJustCreatedId(null); // 到位后清标记
  return; // 标记还在 = 刚建的会话，跳过加载历史
}
```

**必讲的三个点**：
1. 为什么用 `getState()` 而不是 selector 订阅？——把 `justCreatedId` 放进依赖数组，清标记会触发 useEffect 重跑，重跑时标记已空、保护失效，形成"清标记→重跑→覆盖"自我触发链。`getState()` 读不建立订阅，清标记不触发任何东西。
2. 为什么放 store 不放 `useRef`？——ref 存在组件实例内，组件重建就丢；store 跨实例存活。
3. 五轮 debug 的演进线索：ref 失败 → 组件重建 → Zustand → useEffect 依赖自我触发，完整的排查故事本身就是面试亮点。

### 4.3 服务端：RAG 前置 + ChatOpenAI 流式 + 中断 ⭐⭐⭐（面试点）

`app/api/chat/route.ts` 的骨架：

```ts
// ① RAG 前置：绑了知识库就检索，拼进 system（检索失败降级为普通对话，不阻塞聊天）
if (kbId) {
  const lastUserMsg = [...messages].reverse().find((m) => m.role === "user");
  const context = await retrieveContext(kbId, lastUserMsg.content, 3);
  if (context) finalSystem = buildRagSystemPrompt(context, finalSystem);
}

// ② 中断控制：超时 + 客户端中断联动
const upstreamController = new AbortController();
const timeoutId = setTimeout(() => upstreamController.abort(), 30000);
request.signal.addEventListener("abort", () => upstreamController.abort());

// ③ 调用模型（阶段 16 重构后，不再手写 SSE 解析）
const stream = await model.stream(langchainMessages, { signal: upstreamController.signal });

// ④ 把 async iterable 转成 ReadableStream 返回，前端读取方式不变
for await (const chunk of stream) {
  if (typeof chunk.content === "string" && chunk.content) {
    controller.enqueue(encoder.encode(chunk.content));
  }
}
```

**必讲的两个点**：

- **五环中断链路**（阶段 10）：前端点"停止" → `abortRef.current.abort()` → fetch 的 `signal` → 服务端 `request.signal` 的 abort 监听 → `upstreamController.abort()` → `model.stream` 抛 AbortError → catch 里区分"用户主动停（正常结束流）"和"真错误"。`abortRef` 是跨函数共享的"遥控器盒子"：`handleSend` 创建 controller 放进去，`handleStop` 取出来按。
- **裸 fetch vs ChatOpenAI 对比**（阶段 16）：旧版自己拼 SSE 请求体、按行解析 `data:` 行、处理 `[DONE]`、JSON.parse 容错；新版 `model.stream()` 返回 async iterable，协议细节全交给 LangChain。重构时**请求体解析和 RAG 前置一行没动**——这就是"分层隔离"的证明。旧版代码在 route.ts 的大段注释里和 git 历史（ad2b664 提交）都能找到。

### 4.4 RAG 三层 ⭐⭐⭐（面试点）

**向量库抽象层**（`lib/vectorstore.ts`）——最关键的工程决策：

```ts
export interface VectorStore {
  addDocuments(kbId: string, chunks: string[], meta: Record<string, unknown>): Promise<void>;
  similaritySearch(kbId: string, query: string, k: number): Promise<string[]>;
  delete(kbId: string): Promise<void>;
}

// 业务代码只依赖这个接口。当前 Memory 实现，以后换 Chroma 只改这一行：
export const vectorStore: VectorStore = new MemoryStore();
```

必讲：为什么抽象（解耦/可测试/面试可讲选型）；三方案对比——**Memory**（纯内存、重启重嵌入、零依赖）、**Chroma**（Docker 持久化、生产可用）、**FAISS**（本地文件、Windows 编译坑大）；Memory 无命名空间，用 `Map<kbId, MemoryVectorStore>` 隔离各知识库。

**业务逻辑层**（`lib/rag.ts`）：
- `splitText`：RecursiveCharacterTextSplitter，chunkSize 500 / overlap 50。为什么切块：上下文窗口有限 + 检索要精准定位（问什么只想找出讲什么的那一段）。
- `indexDocument`：切块 + 嵌入 + 入库，返回块数存 SQLite 当元数据。
- `retrieveContext`：top-3 检索，编号拼成"片段1/片段2"。
- `buildRagSystemPrompt`：包装成"你是知识库问答助手…资料不足要明确说明，不要编造"。

**模型工厂**（`lib/langchain.ts`）：ChatOpenAI + OpenAIEmbeddings 用 `globalThis` 单例防热重载重复创建。

### 4.5 数据层 ⭐（一句话带过）

- `db.ts`：`node:sqlite` 单例连接；`PRAGMA foreign_keys = ON`（SQLite 默认关外键，不开则 ON DELETE CASCADE 不生效）；手动封装 `db_begin/commit/rollback` 三个事务函数。四张表：conversations、messages、knowledge_bases、documents——**向量不进 SQLite，只存元数据**。
- `queries.ts`：全部 prepared statements 防注入（`?` 占位符），蛇形→驼峰字段映射，route.ts 不直接写 SQL。
- `store.ts`：Zustand store 结构见 4.2；`refreshConversations`/`refreshKnowledgeBases` 是 action 里发 fetch 的示例。
