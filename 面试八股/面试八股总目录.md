> 所有题目都**直接对应项目里的真实代码和踩坑**，不是空泛的八股。

## 四种题型的意思

| 题型 | 是什么 | 举例 |
|---|---|---|
| **概念八股** | 定义题，讲清"是什么" | "什么是受控组件"、"useEffect 依赖数组是干嘛的" |
| **项目设计决策题** | 结合项目的"为什么这么做" | "为什么用 Zustand 不用 Redux"、"为什么 justCreatedId 用 getState 读" |
| **排查/调试题** | STAR 法描述真实排查过程 | "用户反馈消息闪烁后消失，你怎么排查的" |
| **进阶追问/性能题** | 极端场景下的应对 | "文档量到 10 万篇，RAG 怎么优化" |

每份分主题文档都包含这四种题型，标了【概念】【决策】【排查】【追问】前缀。

## 面试时怎么用这个项目（核心心法）

### 1. 每个回答都"落到项目"

```
❌ 弱答："useEffect 依赖数组控制 effect 何时重新执行"
✅ 强答："useEffect 依赖数组控制 effect 何时重新执行。
        我项目里 ChatBox 加载会话历史就靠它，依赖 [currentId]。
        而且我踩过一个坑——把 justCreatedId 放进依赖数组，
        导致清标记时触发自我重跑，覆盖了消息，最后改用 getState 读才解决。"
```

### 2. 准备 2-3 个"故事"

面试官最爱听的是**真实排查故事**。你项目里有现成的顶级素材：

| 故事 | 出处（在项目根目录） | 价值 |
|---|---|---|
| **五轮 debug 竞态 bug** | [`../12b.会话持久化补充.md`](../12b.会话持久化补充.md) | 顶级素材：从 ref 失败 → 组件重建 → Zustand → 依赖自我触发 |
| **裸 fetch vs ChatOpenAI 重构** | [`../16.路线B重构.md`](../16.路线B重构.md) | 体现技术对比和判断 |
| **向量库选型三方案对比** | [`../15.RAG知识库.md`](../15.RAG知识库.md) | 体现工程取舍 |
| **SQLite 外键默认关闭的坑** | [`../SQLite速通.md`](../SQLite速通.md) | 体现踩坑和原理理解 |

### 3. 主动引导到强项

面试官问 useEffect，你答完概念后**主动引**："这个我在项目里深有体会，五轮 debug 才定位到一个 useEffect 依赖自我触发的 bug……"——把话题拉到你最熟的地方。

## 下一步建议

1. **先通读四份分主题文档**，把题目过一遍
2. **挑出你答不顺的题**，重点复习对应的项目代码
3. **把"五轮 debug"故事练熟**，能流畅讲 3-5 分钟（这是杀手锏）
4. **模拟面试**：对着题目自问自答，卡壳的回去补

面试前一晚，过一遍这个总目录 + 默念一遍五轮 debug 故事，就够了。
